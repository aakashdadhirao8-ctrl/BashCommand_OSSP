Through this skill, I gained a better understanding of the Linux development environment and how the operating system handles processes and system-level activities. I learned how to work with a Linux virtual machine and set up the GCC compiler to compile and execute C programs. I also learned how to create and maintain a Git repository with a structured project organization, allowing source code, executable files, and other project components to be managed efficiently. In addition, I understood the basic working of the Linux shell, including how commands entered by users are interpreted and executed. I also learned about Makefiles and their importance in automating the compilation process, which reduces the need to manually type compilation commands repeatedly.
An important part of this skill was learning about process abstraction in Linux. I understood that whenever a program is executed, the operating system creates a process and allocates the necessary resources such as CPU time, memory, and other system resources. Each process is managed by the Linux kernel and contains important information such as its Process ID (PID), Parent Process ID (PPID), current state, and resource usage. I learned that process abstraction hides the complexity of the physical hardware from applications and provides them with a controlled environment for execution. Because of this, multiple programs can execute at the same time while the operating system manages and distributes the available resources.
I also learned about the fork() system call and its role in creating processes. When a process calls fork(), the existing process becomes the parent process and a new child process is created. The child process initially receives a copy of the parent's process information, but after creation, both processes can continue their execution independently. I learned how the return value of fork() helps identify whether the program is executing in the parent or child process. This gave me a clear understanding of process creation and the relationship between parent and child processes. I also understood that processes can form a hierarchical structure, where a parent process can create one or more child processes and form a process tree.
Another important concept covered in this skill was the exec() family of system calls. I understood that fork() is responsible for creating a new process, whereas exec() is used to replace the existing program within a process with another program. This difference is important when executing commands in Linux. A typical approach is for a shell or parent process to create a child process using fork(), after which the child uses an exec() function to execute the required command. I also learned about different functions belonging to the exec() family, including execl(), execlp(), execv(), and execvp(), and understood that each provides different methods for specifying the program and its arguments.
I further developed my understanding of parent-child process relationships by examining process IDs and process hierarchies. By observing PIDs and process trees, I learned how Linux maintains connections between different processes. I also learned that a parent process can use the wait() system call to wait for a child process to complete. This synchronization mechanism ensures that the parent can control its execution based on the termination of its child. It can also receive information about how the child process ended. This helped me understand how process creation, execution, synchronization, and termination are connected as important stages of process management.
Finally, I learned about the role of system calls in providing communication between user-level programs and the Linux kernel. I explored system call tracing concepts and tools such as strace to understand the operations performed internally when a program or Linux command is executed. System calls provide programs with controlled access to kernel services, including process creation, file handling, memory management, and program execution. By studying system call traces, I understood that even a simple command entered in the terminal may require multiple interactions between user-level software and the Linux kernel. Overall, this skill helped me develop a strong understanding of the Linux process model, process creation using fork(), program execution using the exec() family, parent-child synchronization, process hierarchy, shell functionality, and the role of system calls in connecting applications with the operating system kernel.
